# Architecture

## Overview

This project implements a local-first Retrieval-Augmented Generation pipeline for mixed-format document intelligence.

The application is designed around three product goals:

- Reliable document parsing across text and tabular formats
- Grounded answer generation with source context
- Practical runtime behavior on developer hardware

## Runtime Components

- UI and workflow orchestration: Streamlit (`app.py`)
- Retriever embeddings: `nomic-ai/nomic-embed-text-v2-moe` via sentence-transformers
- Vector store: ChromaDB persistent collection (`document_chunks`)
- Generator model: `meta-llama/Llama-3.2-1B-Instruct`
- Translation models: Helsinki-NLP Marian models with multilingual fallback

## Data Flow

1. User uploads files in the UI.
2. Files are parsed by type.
3. Optional translation runs before indexing.
4. Content is chunked with metadata.
5. Chunks are embedded and stored in ChromaDB.
6. User question is embedded and top-k chunks are retrieved.
7. Prompt is assembled from retrieved context and conversation history.
8. LLM generates response and metrics are reported.

## File Processing Strategy

### Text Documents (PDF, DOCX)

- Parsed into page-like units.
- Token-based chunking (`cl100k_base`) maintains bounded prompt size.
- Metadata includes filename, page number, and content type.

### Tabular Documents (XLSX/XLS, CSV)

- Structure summary chunk is generated first.
- Chunking strategy supports:
  - Row-based
  - Column-based
  - Semantic grouping
  - Auto-inference based on data characteristics
- Metadata includes sheet, row/column ranges, and semantic grouping labels where applicable.

## Retrieval and Generation

- Query embedding is generated using the same embedding model as the index.
- ChromaDB similarity search returns top-k chunks.
- Prompt includes:
  - system instructions
  - recent conversation context
  - retrieved chunks with source metadata
  - user query
- Generation uses sampling with controlled max token output.

## Summarization Pipeline

- Full document text is reconstructed for summarization.
- Large documents use representative-section selection to avoid prompt overflow.
- Abstractive summary is generated by the LLM.
- Extractive reference summary is computed for comparison.
- ROUGE metrics provide rough quality signals.

## Operational Concerns

- First run downloads model weights and caches locally.
- Temporary files are created during upload processing and cleaned after use.
- GPU is used when available; CPU fallback is automatic.
- ChromaDB local persistence allows repeated sessions without re-embedding unchanged content.

## Trade-offs

- A compact generator model improves local usability but may reduce answer depth for complex prompts.
- Tabular semantic chunking improves relevance on grouped datasets but may add preprocessing overhead.
- Translation before indexing improves multilingual retrieval consistency at the cost of ingestion latency.

## Scale Notes

For larger deployments, recommended upgrades are:

- Move vector storage to a managed service with backup and observability
- Add document deduplication and content hashing
- Introduce async job handling for translation and summarization
- Add structured evaluation datasets for retrieval and response quality
